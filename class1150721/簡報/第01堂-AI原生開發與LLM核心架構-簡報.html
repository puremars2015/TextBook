核心概念 1

大語言模型（LLM）是什麼？

大語言模型是一種以海量文字資料訓練而成的 AI 系統，能夠理解並生成自然語言。

一個簡單的比喻

想像有一位助理，他從小閱讀了幾乎所有的書籍、文章、程式文件與對話紀錄。當你給他一個問題或指令，他會根據所有學過的知識生成一個最合理的回應。這就是 LLM 的運作方式。

核心概念 1

LLM 的核心能力與產業應用

核心能力

  • 文字生成：根據 Prompt 產出文字內容
  • 語意理解：理解語境與隱含意圖
  • 指令遵循：依指令執行特定任務
  • 推理與分析：多步驟邏輯推論

產業實際應用

  • 客服自動回覆：全天候回應
  • 文件摘要與分析
  • 程式碼自動生成
  • 行銷文案量產
  • 資料分類與標記
核心概念 2

AI Agent 系統架構

AI Agent 是一種能夠自主執行複雜任務的 AI 系統，具有完整的「感知 → 思考 → 規劃 → 行動」迴圈。

直覺的比喻

你告訴助理：「幫我調查三個競爭對手的定價，整理成 Excel 報表後寄給我。」助理會自行規劃步驟：搜尋網路 → 瀏覽官網 → 紀錄資料 → 開啟 Excel → 填寫資料 → 寄送郵件，全程不需要你一步一步指示。

核心概念 2

Agent 的四大組成要素

使用者任務指令
↓
大腦（LLM）理解任務、制定決策
↓
規劃器（Planner）將複雜任務拆解為可執行步驟
↓
工具集（Tools）瀏覽器、程式執行器、API、檔案讀寫…
↓
記憶體（Memory）儲存過去的對話與執行紀錄
核心概念 3

什麼是 Vibe Coding？

Vibe Coding 是一種以自然語言驅動程式碼生成的開發方式。你不需要自己寫每一行程式語法，只需要用白話文描述你想要做的事，由 AI 工具（如 GitHub Copilot）幫你生成可執行的程式碼。

核心概念 3

Vibe Coding 的長處與限制

長處
  • 大幅降低程式設計的學習門檻
  • 快速將想法轉化為可執行工具
  • 讓非技術業務人員也能構建流程
  • 加快原型（Prototype）開發速度
限制
  • AI 生成的程式碼可能有錯，必須人工驗證
  • 對高安全需求系統有侷限
  • 需求描述不清，結果可能不符期望
  • 不適合直接用於高精確度核心系統
核心概念 3

傳統開發 vs. Vibe Coding

傳統開發Vibe Coding
前置要求熟悉程式語法與演算法能清楚描述需求
開發速度依工程師熟練度而定快速產出原型
結果可靠性工程師掌控需人工驗證
適合場景核心系統、高安全性自動化工具、快速驗證
核心概念 4

Hermes 平台簡介

Hermes Agent 是一套開源的 AI Agent 閘道器，透過 Docker 或原生安裝部署，將 LLM 與訊息平台（Telegram、Discord）及各式工具串接起來，讓使用者像聊天一樣操作 Agent。

Telegram / Discord
↓
Hermes Gateway閘道器
↓
Agent（大腦）你在對話的 AI
↓
Tools（手）瀏覽器、終端機、檔案、搜尋、排程…
  • 開源、可自架部署，資料掌握在自己手上
  • 透過 Gateway 串接多種訊息平台，用聊天介面操作 Agent
  • 內建瀏覽器操作、網頁搜尋、Cron Job 定時監控等工具
  • 支援條件觸發推播，避免資訊轟炸；提供 Control UI 視覺化管理

本課程後續堂次將實際使用 Hermes Agent 構建各種自動化查詢與監控系統。

核心概念 5

LLM 與 Agent 的資安風險

風險類型說明防護方向
Prompt Injection惡意輸入操控 AI 執行非預期行為對外部輸入進行驗證與過濾
資料洩漏Agent 可能不慎將敏感資料傳送外部 LLM避免將機密資料送入外部 API
過度授權Agent 被賦予超出任務所需的權限遵循「最小權限原則」
幻覺 HallucinationLLM 生成看似合理但錯誤的資訊重要輸出需人工核實
重要觀念：LLM 有時會「自信地給出錯誤答案」。在 Agent 系統中，錯誤決策會直接驅動工具執行行動——務必在關鍵決策點加入人工確認機制。

課堂示範 2

用 Vibe Coding 生成第一個 AI 程式

在 Copilot Chat 輸入需求：

請幫我用 Python 寫一個程式，讓我在終端機輸入文字，
程式會呼叫 OpenAI 的 API，並把 AI 的回應顯示在螢幕上。
需要支援連續對話，輸入 "exit" 就結束程式。
請記得從環境變數讀取 API Key，不要把 Key 寫在程式碼裡。

觀察重點：API Key 的讀取方式、對話歷史的儲存方式、請求與回應的流程。接著加入「讀取/寫入檔案」工具——當 AI 有了「工具」，它就從聊天機器人升級為可以做事的代理人。

程式碼範例（虛擬碼）

基礎 LLM 對話程式

載入 openai 套件
設定 API_KEY = 從環境變數讀取("OPENAI_API_KEY")

對話歷史 = []

重複執行:
    讀取 使用者輸入
    如果 使用者輸入 == "exit":
        顯示 "再見！"
        結束程式

    將「使用者訊息」加入對話歷史
    呼叫 LLM API:
        傳入: [模型名稱, 對話歷史]
        接收: AI 回應文字

    將「AI 回應」加入對話歷史
    顯示 AI 回應
程式碼範例（虛擬碼）

加入工具調用的基礎 Agent 機制

工具A: 讀取檔案(檔案路徑) → 回傳檔案內文字
工具B: 寫入檔案(檔案路徑, 文字內容) → 儲存到檔案
工具清單 = [工具A, 工具B]

函式 Agent執行(任務描述):
    重複執行 直到任務完成:
        給 LLM 的輸入 = {
            系統指令: "你是一個能操作檔案的 AI 助理",
            任務: 任務描述,
            可用工具: 工具清單的名稱與說明,
            過去執行結果: 執行歷史
        }
        LLM 決策 = 呼叫 LLM(給 LLM 的輸入)

        如果 LLM 決定使用某個工具:
            執行該工具，取得結果
            將結果記錄到執行歷史
        否則（LLM 認為任務完成）:
            回傳最終答案
