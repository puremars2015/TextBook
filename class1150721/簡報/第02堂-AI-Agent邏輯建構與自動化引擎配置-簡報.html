核心概念 1

自動化引擎：任務如何變成行動？

不論是人工 SOP 或 AI Agent，自動化流程都可拆解成三個核心元素。

輸入 Input任務、資料、觸發事件
→
決策邏輯條件判斷、規劃、選擇下一步
→
輸出 Output結果、通知、寫檔、寄信
AI Agent 的特別之處：決策邏輯可由 LLM 動態產生，不必將每條規則完全寫死。
核心概念 1

Agent 的完整工作週期

1. 接收任務使用者或系統給出指令
2. 拆解步驟判斷目標，規劃可執行動作
3. 執行行動呼叫工具，完成子任務
4. 確認結果判斷成功、失敗或需要資訊
5. 回報完成整理結果並交還給使用者
若未完成或發生錯誤，帶著新的觀察回到「拆解步驟」，再決定下一個行動。
核心概念 2

條件判斷：讓流程會選路

條件判斷的本質是：如果滿足條件，就採取對應動作；否則選擇另一條路。

收到一封新郵件
主旨 + 內文
郵件意圖是什麼？
含「請款」或付款語意
轉交財務處理
含抱怨、退款或不滿
標示高優先，轉客服主管
其他一般問題
生成標準回覆草稿
核心概念 2

條件判斷的程式思維

如果 條件A 為真:
    執行動作A
否則如果 條件B 為真:
    執行動作B
否則:
    執行預設動作

在 Agent 中的應用

  • 若 LLM 決定「呼叫工具」：執行指定工具
  • 若 LLM 判斷「任務完成」：回傳最終答案
  • 若資訊不足：向使用者提出澄清問題
  • 若工具失敗：重試、改用替代方案或轉人工

設計提醒：條件必須可觀察、可判斷。模糊的條件，會讓自動化流程走向不可預期。

核心概念 2

迴圈：讓 Agent 持續推進任務

計數迴圈

重複固定次數，或逐筆處理一份明確清單。

範例：逐一處理資料夾中的 100 份報表。

條件迴圈

持續執行，直到任務完成或符合停止條件。

範例：反覆呼叫 API，直到取得有效回應。

Agent 最常使用條件迴圈：思考 → 行動 → 觀察結果 → 再思考。

核心概念 2

迴圈要有「安全出口」

重複執行 直到 任務完成:
    思考當前狀態
    決定下一個行動
    執行行動
    觀察結果
    更新對任務的理解

避免無限迴圈

  • 設定明確的任務完成條件
  • 設定最大步驟數或最大重試次數
  • 記錄每次嘗試的結果，避免重複做同一件事
  • 達到上限時，交由人工決定下一步
核心概念 3

錯誤不是例外，是流程的一部分

網路中斷、API 逾時、資料格式不符都會發生。好的自動化系統需要先設想失敗，再設計回應。

步驟要回答的問題例子
偵測哪裡出錯？API 回應逾時、檔案不存在
分類能不能重試？暫時斷線可以重試；權限不足不應重試
補償下一步怎麼做？等待後重試、切換備用模型、通知人工
核心概念 3

容錯策略：為流程預備 Plan B

重試 Retry

適合網路暫時不穩、API 偶發逾時。設定次數上限，不要無止盡重試。

漸進等待 Backoff

每次重試等待更久，避免在 API 限流時持續施壓。

替代方案 Fallback

主要服務故障時改用備援資料來源、備用模型或暫存資料。

人工介入

遇到高風險或無法修復的錯誤，要通知能做決策的人。

核心概念 3

一次可靠的重試流程

呼叫 API送出任務，設定逾時時間。
→
成功？成功就使用結果；失敗則記錄錯誤類型。
→
可重試？是：等待後再試；否：切換方案或請人工處理。
對 嘗試次數 從 1 到 最大重試次數:
    嘗試呼叫 API
    如果成功: 回傳結果
    如果是暫時性錯誤: 等待後重試
    如果是不可恢復錯誤: 記錄原因並停止

回傳「已達重試上限，請人工檢查」
核心概念 4

工具調用：讓 Agent 從會說變成會做

工具是一個具有明確輸入與輸出的函式。LLM 負責決定何時使用哪個工具，程式負責真正執行。

搜尋工具搜尋網路或資料庫
例：查詢競品資訊
檔案工具讀取與寫入檔案
例：處理 CSV、TXT
計算工具執行精確運算
例：計算機、Python
通訊工具發送郵件與訊息
例：Outlook、LINE
瀏覽器工具開啟網頁並操作
例：Playwright
核心概念 4

工具調用的完整閉環

使用者任務「找出本週三家競品的價格」
LLM 分析判斷需要搜尋與整理資訊
呼叫工具傳入關鍵字與網址等參數
取得結果工具回傳資料或錯誤訊息
LLM 再決策繼續調查，或整理為最終答案
LLM 不直接碰觸電腦或資料庫；工具執行層必須負責權限控管、驗證與記錄。
實作一

用 Copilot 建立 LLM 對話程式

1

建立環境

安裝 openai 套件，並確認 Python 環境可正常執行。

2

設定憑證

從環境變數讀取 OPENAI_API_KEY，不要將金鑰寫入程式碼。

3

描述需求

請 Copilot 寫出支援連續對話、保留歷史與錯誤處理的程式。

4

檢視與測試

理解 messages、try / except 和 os.environ 的用途。

實作一

請 Copilot 協助實作的 Prompt

請幫我用 Python 寫一個與 OpenAI GPT 對話的程式：
1. 從環境變數讀取 API Key，不要寫死在程式裡
2. 支援連續對話，必須保存對話歷史
3. 使用者輸入 "exit" 就結束程式
4. 程式需要基本錯誤處理，例如 API 連線失敗時顯示友善訊息
5. 對暫時性錯誤最多重試 3 次
檢查重點：每輪對話有沒有同時記錄「使用者訊息」與「AI 回應」？金鑰是否只從環境變數讀取？
實作二

加入檔案工具，升級為基礎 Agent

工具A：read_file(path)
    輸入：檔案路徑
    輸出：檔案文字或錯誤訊息

工具B：write_file(path, content)
    輸入：路徑、文字內容
    輸出：成功或失敗狀態

Agent 執行順序

  1. LLM 判斷是否需要工具
  2. 程式檢查工具與參數是否合法
  3. 執行對應函式，取得結果
  4. 將結果傳回 LLM，讓它決定下一步
實作二

工具調用的 Agent 虛擬碼

函式 Agent執行(使用者指令):
    對話歷史 = [系統提示 + 工具說明 + 使用者指令]

    重複執行 最多 10 次:
        LLM回應 = 呼叫LLM(對話歷史)

        如果 LLM回應.類型 == "呼叫工具":
            工具名 = LLM回應.工具名稱
            參數 = LLM回應.工具參數
            工具結果 = 工具清單[工具名](參數)
            將工具結果加入對話歷史
        否則如果 LLM回應.類型 == "最終回答":
            回傳 LLM回應.內容

    回傳 "已達最大步驟數，任務未完成"

安全觀念：只開放需要的工具與資料夾；所有寫入、刪除或外部傳送操作都應設計確認機制。

課後作業

把今天的 Agent 再往前推一步

1. 擴充工具

在課堂 Agent 中新增第三個工具：列出指定資料夾內所有檔案。讓 Agent 知道「有哪些資料」可以操作。

2. 刻意測試失敗

嘗試讀取不存在的檔案，觀察程式回應；改寫錯誤訊息，讓使用者知道發生什麼事、下一步該做什麼。
