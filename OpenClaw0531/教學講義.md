# OpenClaw AI Agent 教學講義

## 前言

本文是為了讓大家能夠快速上手OpenClaw AI Agent而寫的教學講義。希望透過這篇文章，能夠幫助大家了解什麼是AI Agent，以及如何使用OpenClaw來創建自己的AI Agent。

我們會盡量從不需要專業知識的角度，以及現在眾人隨手可觸碰的地方，讓大家知道AI Agent是什麼，以及AI Agent是怎麼工作的。

## 1. 什麼是 AI Agent？

這問題要從AI說起，狹義來說，我們這邊指的是所謂的基於深度學習的大語言模型的人工智慧。目前最常見的就是OpenAI的ChatGPT，還有Google的Gemini，Anthropic的Claude，微軟的Copilot等等。這些都是基於大語言模型的人工智慧。

基本上從操作面來說，就是你輸入一段文字，經過計算之後，他也回應給你一段文字。

然而，僅有文字的輸出，雖然也可以協助我們撰寫信件，準備文案草稿，甚至是回答我們的問題，但僅有如此，用起來會有很多的限制，因為他只能回應文字，無法幫助我們完成一些需要操作的任務。或著說，其實人類生活"實做"有時候是很簡單，但很費力的一個問題。我們需要的不只是一個出idea的顧問，更多時候我們需要的是一個真的可以直接把事情做好的人。

所以這時候，如果讓AI不只可以回應文字，還可以幫我們操作一些工具，甚至是幫我們直接把事情做好，那麼就會大大提升AI的實用性。

所以AI Agent的概念就這樣誕生了。AI Agent就是一個可以幫助我們完成任務的人工智慧，他不僅可以回應文字，還可以幫我們操作工具，甚至是幫我們直接把事情做好。


## 2. AI Agent的工作原理-1

AI Agent的工作原理其實很簡單，本質上就是讓他去"命令"一些工具，來幫助我們完成任務。

你可以想像成一個人，他有一個大腦，這個大腦就是AI，他可以思考，分析問題，然後透過你的大腦神經連結的工具，並把命令派發給工具，然後操作一些工具，來幫助你完成任務。

好，那到底LLM怎麼去命令工具呢？其實很簡單，LLM本質上就是一個文字生成器，他會根據你給他的提示，來生成一段文字，這段文字就是他對工具的命令。我們可以利用所謂的harness engineering的技術，來讓LLM生成的文字符合工具的命令格式，這樣LLM就可以直接把命令派發給工具，來幫助我們完成任務。

例如：
我想讓AI Agent幫我查詢一下今天的天氣，那麼我就可以給他一個提示，讓他生成一段文字，這段文字就是他對工具的命令，例如："請幫我查詢一下今天的天氣"。

然後LLM就會根據這個提示，生成一段文字，我們會透過要求LLM生成的文字符合工具的命令格式，常常使用類似JSON的格式，來讓LLM生成的文字符合工具的命令格式，例如：
```json
{
  "command": "查詢天氣",
  "parameters": {
    "日期": "今天"
  }
}
```

然後工具函數就會根據這段文字來執行動作，並返回執行結果，而這個執行結果常常也是json格式，例如：
```json
{
  "result": "今天的天氣是晴天，氣溫25度。"
}
```

然後LLM會判斷這個查詢的結果是否符合我們的需求，如果符合，就可以發出訊息用來給我們的回覆，那這個訊息文本本身可能也是json格式，例如：
```json
{
  "message": "今天的天氣是晴天，氣溫25度。"
}
```

就可以繼續透過harness engineering的技術，將這個訊息轉換成我們需要的格式，然後回傳給使用者。


## 3. AI Agent的工作原理-2

AI Agent是怎麼可以這樣循環觀察、思考、行動的呢？其實很簡單，AI Agent的工作原理就是一個循環的過程，這個過程可以分為三個步驟：觀察、思考、行動。

1. 觀察：AI Agent會觀察周圍的環境，收集相關的資訊，這些資訊可以是來自於使用者的輸入，也可以是來自於工具的回饋，甚至是來自於外部的資料來源，例如網路上的資料。

2. 思考：AI Agent會根據觀察到的資訊，進行分析和思考，然後決定下一步要做什麼，這個過程就是AI Agent的思考過程。

3. 行動：AI Agent會根據思考的結果，來決定要執行什麼動作，這個動作可以是回應使用者的訊息，也可以是操作工具來完成任務。

然後這個過程就會不斷的循環下去，AI Agent會不斷的觀察、思考、行動，來幫助我們完成任務。

如果用現在主流的AI Agent設計方式來看，例如 OpenClaw 這類 coding agent，實作上通常不會只是單純寫一個 `while True` 然後一直跑下去。更精確地說，它比較像是一個「帶有狀態的決策迴圈」：每一輪都要讀取目前上下文、檢查任務目標、決定是否呼叫工具、接收工具結果，最後再判斷是否完成任務。

也就是說，現代 Agent 的核心通常不只是「循環」，而是下面這幾個元件一起配合：

1. 狀態（state）：保存目前任務、對話歷史、工具執行結果、暫存推理資訊。
2. 決策器（policy / planner）：由 LLM 根據目前狀態判斷下一步是要回覆、呼叫工具、還是請使用者補充資訊。
3. 工具執行層（tool executor）：真的去執行搜尋、讀檔、寫檔、查資料庫、呼叫 API 等動作。
4. 控制器（controller）：負責限制最大步數、權限、安全規則，以及停止條件。

如果用比較接近現在主流 Agent 框架的寫法，可以想像成這樣：
```python
state = {
  "messages": [{"role": "user", "content": user_input}],
  "step_count": 0,
  "max_steps": 10,
  "done": False,
}

while not state["done"] and state["step_count"] < state["max_steps"]:
  # 1. 讓模型根據目前狀態決定下一步
  decision = agent_model(state["messages"])

  if decision["type"] == "final_answer":
    final_response = decision["content"]
    state["done"] = True

  elif decision["type"] == "tool_call":
    # 2. 執行工具
    tool_result = run_tool(
      name=decision["tool_name"],
      args=decision["arguments"]
    )

    # 3. 把工具結果寫回狀態，讓下一輪可以繼續推理
    state["messages"].append({"role": "assistant", "content": decision})
    state["messages"].append({"role": "tool", "content": tool_result})

  elif decision["type"] == "ask_user":
    final_response = decision["question"]
    state["done"] = True

  else:
    final_response = "任務無法安全繼續，流程已停止。"
    state["done"] = True

  state["step_count"] += 1
```

這裡你會發現，Agent 並不是每一輪都固定做一樣的事，而是每一輪都會先根據目前的狀態做判斷。換句話說，現在主流的 Agent 比較像是「LLM 負責決策，系統負責執行與管控」，而不是只有一個單純的思考函數。

那這個 loop 什麼時候會結束呢？以現在常見的設計來說，通常有幾種停止條件：

1. LLM 已經產生最終答案，不需要再呼叫工具。
2. Agent 判斷資訊不足，改成向使用者追問。
3. 已經達到最大步數，避免無限循環或成本失控。
4. 工具執行失敗，或觸發權限與安全限制，所以流程被中止。

因此，現代 AI Agent 的 while loop 比較像是一個「受控的任務執行迴圈」，而不是沒有邊界的無限迴圈。這也是為什麼像 OpenClaw 這類 Agent 系統，除了模型本身之外，還需要額外設計狀態管理、工具介面、錯誤處理與停止機制。

## 6. 怎麼使用OpenClaw,可以用在哪些地方？

如果要真的開始使用OpenClaw，最實際的做法不是一開始就做一個無所不能的大型 Agent，而是先挑一個明確、可驗證、可控管的任務來做。換句話說，我們應該先從「輸入明確、流程固定、結果容易檢查」的工作開始，這樣比較容易成功。

一般來說，使用OpenClaw建立一個實用 Agent，大致可以分成下面幾個步驟：

1. 定義任務目標：先講清楚 Agent 到底要幫你完成什麼事。
2. 選擇可用工具：例如 Gmail、Google Calendar、瀏覽器、自訂 API、檔案系統等。
3. 設計執行規則：哪些操作可以自動完成，哪些操作一定要先詢問使用者。
4. 測試與修正：先用少量資料測試，確認 Agent 不會做出錯誤行動。

下面我們就用幾個常見情境，來看 OpenClaw 可以實際應用在哪些地方。

### OpenCode 安裝步驟

OpenCode 比較適合拿來當成「CLI 版的 AI 修復助手」。當你在安裝 OpenClaw、修改設定檔、排查錯誤訊息時，可以直接在專案資料夾裡呼叫 OpenCode 幫你讀專案與分析問題。

Windows 下最常見的安裝方式如下：

1. 先安裝 Node.js，建議使用目前穩定版或 LTS 版本。
2. 開啟 PowerShell。
3. 執行安裝指令：

```powershell
npm install -g opencode-ai
```

4. 安裝完成後，輸入下面指令確認是否安裝成功：

```powershell
opencode --version
```

如果你的電腦平常使用套件管理器，也可以改用下面其中一種方式：

```powershell
choco install opencode
# 或
scoop install opencode
```

安裝完成後，建議先切換到你的專案資料夾，再啟動：

```powershell
cd 你的專案資料夾
opencode
```

第一次使用時，你可以直接丟一個很具體的問題給它，例如：「請幫我檢查這個專案為什麼無法啟動，先閱讀錯誤訊息，再提出修復方案。」這樣在 OpenClaw 壞掉時，你還有另一個 AI CLI 可以幫忙排錯。

如果你是 Windows 使用者，但後續要做比較重度的終端機操作、程式碼搜尋與工具鏈整合，實務上也可以考慮搭配 WSL2，通常相容性會更穩定。

### OpenClaw 安裝步驟

OpenClaw 是這份講義的主角，所以安裝時建議先把環境打好，再做後面的 Agent 與 Skill 練習。最基本的前置條件是：

1. 已安裝 Node.js 與 npm。
2. PowerShell 或 Windows Terminal 可正常執行。
3. 已準備好至少一組可用的 LLM API Key，例如 OpenRouter、OpenAI 或其他模型供應商。

安裝流程如下：

1. 開啟 PowerShell。
2. 執行全域安裝：

```powershell
npm install -g openclaw@latest
```

3. 確認版本：

```powershell
openclaw --version
```

4. 第一次啟動時，建議直接執行：

```powershell
openclaw onboard --install-daemon
```

這個指令通常會協助你完成幾件事：

1. 建立初始設定。
2. 安裝或啟用常駐服務。
3. 初始化工作環境。
4. 連接模型設定。
5. 準備後續要用的 Gateway 與 Dashboard。

完成後，可以用下面兩個常用指令確認系統是否正常：

```powershell
openclaw gateway --port 18789 --verbose
openclaw dashboard
```

如果一切正常，Dashboard 通常會開在：

```text
http://127.0.0.1:18789/
```

如果你安裝完卻找不到 `openclaw` 指令，最常見的原因有三個：

1. Node.js 沒有正確安裝。
2. npm 的全域安裝路徑沒有加入 PATH。
3. 安裝完成後沒有重新開啟 PowerShell 視窗。

實務上建議安裝完後，順手再跑一次 `openclaw doctor`。這可以幫你快速檢查環境、設定檔與常見錯誤。

### Hermes Agent 安裝步驟

Hermes Agent 比較偏向另一套獨立的 AI Agent 工具鏈。如果你的課程想讓學生比較不同 Agent 系統的安裝方式，或想示範另一種本機 Agent 使用體驗，就可以把 Hermes 一起裝起來。

目前在 Windows 上有兩種常見方式：

1. Native Windows 安裝：比較方便，但仍屬較新的支援模式。
2. WSL2 安裝：步驟比較長，但通常更穩定。

如果先以課堂實作為主，可以優先用 Windows Native 安裝：

1. 開啟 PowerShell。
2. 執行官方安裝腳本：

```powershell
irm https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.ps1 | iex
```

這個安裝流程通常會協助處理 Hermes 所需的執行環境與依賴。安裝完成後，請關閉目前視窗，再重新開一個新的 PowerShell。

3. 驗證安裝狀態：

```powershell
hermes doctor
```

4. 若檢查正常，再啟動 Hermes：

```powershell
hermes
```

如果你想走較穩定的方式，也可以先安裝 WSL2 與 Ubuntu，再到 Linux 環境中執行：

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
source ~/.bashrc
hermes doctor
```

Hermes 安裝完成後，通常還需要做一次基本設定，例如：

```bash
hermes setup
```

或另外設定模型：

```bash
hermes model
```

這一步通常會要求你提供模型供應商的 API Key，像是 OpenRouter 或其他可相容的 LLM 服務。也就是說，Hermes 的安裝分成兩段：先把程式裝起來，再把模型連接好，這樣它才真的能工作。


### Gmail自動化

Gmail自動化是非常適合初學者入門的場景，因為它的任務邏輯通常很清楚，而且結果也容易檢查。很多日常工作其實都和信件有關，例如：整理未讀信件、分類重要信件、擷取信件重點、草擬回覆內容、甚至依照條件轉寄給相關人員。

例如，我們可以設計一個 OpenClaw Agent，讓它每天早上自動完成以下任務：

1. 讀取昨天晚上到今天早上的新信件。
2. 判斷哪些信件和工作有關，哪些只是通知型郵件。
3. 將重要信件摘要成三到五行重點。
4. 遇到需要回覆的信件時，先產生回信草稿。
5. 在真的寄出前，先讓使用者確認。

這類型的 Agent 很符合現代 Agent 的設計精神，因為它不是單純回答問題，而是會先讀取郵件，再做判斷，接著呼叫對應工具去建立草稿、加標籤、歸檔或提醒使用者確認。

如果要把流程拆開來看，大概會像這樣：

1. 使用者下達目標，例如：「幫我整理今天的工作信件，並產生回覆草稿。」
2. OpenClaw 呼叫 Gmail 相關工具，讀取最新郵件。
3. LLM 分析每封信件的內容與優先順序。
4. Agent 決定要做的動作，例如摘要、分類、草擬回信。
5. 若動作涉及寄信，系統先停下來請使用者確認。

這裡有一個很重要的實務觀念：像「直接寄出信件」這種動作，通常不建議一開始就做成全自動。比較好的設計方式是讓 Agent 先幫你讀、幫你想、幫你寫，但真正送出之前還是保留人工確認。這樣才符合安全、可控、可追蹤的原則。

### Google Calendar行程管理

另一個非常常見的應用，就是把 OpenClaw 當成你的行程助理。它可以協助你整理會議、安排空檔、建立提醒、檢查衝突，甚至依照你的工作習慣提出比較合理的時間建議。

例如你可以對 Agent 說：

「幫我找這週三下午和王先生開會的空檔，預留一小時，並避開我原本的課程時間。」

這時候，一個設計良好的 Agent 並不會立刻亂塞一個會議進去，而是會做幾個步驟：

1. 先讀取你的行事曆。
2. 找出可用時段。
3. 檢查是否有衝突或通勤時間過短的問題。
4. 整理成幾個候選時段。
5. 請你確認後，再建立正式行程。

如果你願意再進一步，也可以讓它結合 Gmail 一起工作。例如當你收到一封約會議的信件，Agent 可以先讀懂信件內容，再去查你的 Google Calendar，最後自動整理出「我這週可安排的三個時段」，並生成回信草稿。這就不是單一工具自動化，而是跨工具協作的 Agent。

Google Calendar 這個場景的教學價值很高，因為它可以讓學員理解兩件事：

1. Agent 需要先取得外部世界的資料，不能只靠模型想像。
2. Agent 的價值不只是新增資料，而是先分析、比較、判斷，再進行操作。

這也正好對應到前面提到的主流架構：狀態管理、工具調用、決策迴圈、停止條件，在這個案例中都會非常明顯。

### 新聞監測與投資輔助

新聞監測是另一種很有代表性的 Agent 任務，因為它需要大量讀取外部資訊、持續追蹤變化，並且把雜亂的資訊整理成可以快速理解的摘要。這類工作很耗時間，但很適合交給 Agent 先做第一輪整理。

例如我們可以建立一個 Agent，專門追蹤：

1. 某幾家公司或產業的最新新聞。
2. 法說會、財報、政策、供應鏈、國際局勢相關消息。
3. 社群平台或新聞網站上的討論熱度變化。

然後每天固定幫你輸出一份整理報告，例如：

1. 今天有哪些重要事件。
2. 哪些消息和你追蹤的標的有關。
3. 哪些內容可能偏向雜訊，不需要太在意。
4. 有哪些訊號值得你再進一步人工判讀。

不過這個場景有一個非常重要的界線必須講清楚：Agent 可以協助你做「資訊整理與決策支援」，但不應該被描述成「自動代替你做投資決策」。比較合理的定位是，它幫你做資料蒐集、摘要、分類、比對與提醒，至於最終投資判斷，仍然應該由人來負責。

如果把這種 Agent 拆成流程，你會看到它通常包含：

1. 爬取或讀取多個資料來源。
2. 萃取和目標公司、產業、關鍵字相關的內容。
3. 去除重複新聞與低品質資訊。
4. 生成摘要，並標記可能影響的重要事件。
5. 將結果寄送到 Email、聊天室、報表或資料庫。

這一類任務很能展現 OpenClaw 的可擴展性，因為你可以慢慢把工具接上去，從單純讀新聞，到結合 Excel、Google Sheet、LINE 通知、Email 報告，最後變成一套完整的情報整理流程。

### 網站開發與維護

如果從現在最熱門的方向來看，網站開發與維護其實正是 AI Agent 最有代表性的應用之一。像 OpenClaw 這類系統，若搭配讀檔、寫檔、搜尋程式碼、執行測試、操作終端機等工具，就可以變成一個協助工程開發的 coding agent。

在這種情境下，Agent 可以做的事情很多，例如：

1. 讀取專案程式碼並理解目前架構。
2. 根據需求修改前端或後端程式。
3. 幫忙補上 API 串接、畫面文案、表單驗證。
4. 執行測試、找出錯誤、修正 bug。
5. 協助維護既有網站內容，例如更新公告、修改頁面資訊、調整版型。

舉例來說，如果你對 Agent 下達一個任務：「請幫我把首頁的活動資訊更新成最新版本，並檢查手機版排版有沒有跑掉。」那麼一個現代 Agent 可能會這樣工作：

1. 先搜尋網站專案中和首頁相關的檔案。
2. 找到活動資訊的資料來源或畫面元件。
3. 修改對應內容。
4. 啟動測試或預覽流程。
5. 檢查是否有錯誤訊息，最後再回報修改結果。

這類應用特別能說明，AI Agent 不是「取代工程師」，而是把很多原本要人手動查、手動改、手動驗證的流程自動化。真正有價值的地方，不是它會寫幾行程式，而是它能在工具鏈之間持續推進任務。

當然，網站開發與維護這個場景也最需要安全控制。因為只要牽涉到改檔、刪檔、部署、寫入資料庫，就必須明確定義哪些操作可以自動執行，哪些操作一定要人工確認。這也是為什麼前面一直強調，現代 Agent 一定要有控制器、權限邊界與停止條件。

## 7. 結語

學習 OpenClaw 的重點，不只是學會怎麼呼叫一個模型，也不是背幾個工具名稱而已。真正重要的是理解：當 LLM 能夠讀取上下文、呼叫工具、根據結果繼續決策，而且整個過程受到系統規則管理時，它就會從一個單純聊天的 AI，變成一個能夠實際完成任務的 Agent。

對初學者來說，最好的練習方式是從一個小場景開始，例如整理 Email、安排行程、摘要新聞，或修改一個簡單網站。先把一條流程做通，再逐步增加工具、狀態與判斷邏輯。當你能把這些部分串起來時，你就不只是「會用 AI」，而是真的開始具備設計 AI Agent 的能力。

如果你能掌握這份講義提到的核心觀念，那麼接下來無論你要學更進階的自動化流程、multi-agent 協作、企業內部工具整合，或是 coding agent 的開發，都會有很好的基礎。
